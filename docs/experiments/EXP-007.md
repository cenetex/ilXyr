## Frozen question

Can a Solomon sparse integer class head learn ZERO.4's five-way Q22 operation
routing surface from the shared training set and reach at least 950,000 exact
selections per million promotion cases on every declared seed?

Identical per-case predictions across all three seeds were frozen as a
secondary robustness gate. A valid completed miss remained `no_go`; it was not
an execution failure and could not authorize tuning against the promotion set.

## What was frozen before evaluation

The NSRL source contract fixed an 8,192-feature, five-class signed integer
perceptron with zero initialization, four epochs, and seeded shuffled training.
Its features were first-token, token, positioned-token, and byte 1–4-gram
counts. The model accepted only Solomon's encoded training file. Prediction
accepted only blinded `id`, `input` rows.

The ilXyr registration merged before evaluation opened and fixed:

- the 9,500-row training SHA-256
  `815fac312664f49eaaa33942828ffa1511fd81091ccd88d47b4480b6c27a5fa4`;
- the 500-row promotion SHA-256
  `9270ea2b72af90235407bd7924a0864b8eba35b2969e1657ed1c15bf04449519`;
- seeds 1, 2, and 3;
- the common `operation_exact_rate_ppm` metric;
- a 950,000 ppm per-seed gate;
- 1,000,000 ppm cross-seed agreement as a secondary source gate;
- exact Zero and NSRL commits and source-file hashes; and
- local CPU execution with no paid compute and offline Rust builds.

All three model files and their training traces were hashed into
`models-frozen.json` while `evaluation_opened` was still `false`. Only then did
the evaluator create the blinded promotion input and record that retraining was
forbidden.

## Conclusion and boundary

The Zero to Solomon Q22 operation-routing bridge passed. The result shows that
the frozen five-way routing capability transfers into this small Solomon
integer class-head surface under the shared bytes, seeds, metric, and verifier.

It does not show arithmetic answer generation, broad language understanding,
or general Solomon model promotion. The commands have strongly separating
prefixes, and the registered feature map can exploit them directly. A successor
experiment is justified only if it changes the scientific question: it should
remove prefix shortcuts and test compositional or paraphrastic transfer on a
new frozen dataset. Repeating Q22 or tuning this class head against the opened
promotion set is not authorized.
