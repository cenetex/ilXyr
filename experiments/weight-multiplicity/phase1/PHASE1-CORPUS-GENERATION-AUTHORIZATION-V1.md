# Phase 1 weight-multiplicity corpus generation authorization

Date: 2026-08-31

Status: authorized with conditions

The client accepts the Phase 0.6 retained-surface preflight and authorizes
generation of the 458,750-record Revision 3 corpus on the reduced
825-representation surface.

Three conditions are binding:

1. The actual eight-worker generation run must measure sustained peak RSS.
   Any worker that exceeds the frozen 8 MiB divergence threshold stops the run
   and places the corpus on Hold. The signed 2 GiB ceiling remains an absolute
   limit, not the operational warning line.
2. A bounded pilot must measure the actual generator's stratum yields. Before
   the first corpus record is created, the runner must write and hash one
   numeric budget using a one-sided 95% yield bound, the measured Phase 0.6
   LiE latency, and the contractual 15% margin. Reaching that limit stops the
   run; it cannot be raised in place.
3. A deterministic sample of generated records must be checked against the
   canonical-name Zero build during generation. Any completed arithmetic
   disagreement immediately places the corpus on Hold. Unavailable checks are
   reported, and at least 95% of selected checks must complete.

The run may use eight persistent LiE workers and two Zero differential
workers. It is limited to one AWS `c6i.4xlarge`, 90 minutes, and an estimated
$1.02 of EC2 compute. Automatic termination is mandatory.

The frozen plan is
`examples/weight-multiplicity/phase1-corpus-plan-v1.json`. The root-system
record is generated by the canonical B/C-repaired Zero source and is frozen
at `examples/weight-multiplicity/phase1-root-systems-v1.json`.

This authorization permits corpus generation, validation, de-duplication,
sealing, and hashing only. It does not permit model training, model
evaluation, source modification, or oracle promotion. The corpus manifest,
hashes, stratum yields, cost record, memory record, and Zero differential
evidence must return for review before anything trains.
