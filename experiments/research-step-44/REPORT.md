## The change to the schedule

The historical Q2.9 language evaluator used sixteen workers. Its recorded
language time was 298.42 seconds. That is context from an earlier model and
case roster. The new comparison will measure its own costs on one fixed host.

The [step44 plan](PLAN.json) fixes sixteen task and language workers for the
full run and two for the tiny checks. Worker `i` scores original case ordinals
whose remainder after division by the worker count is `i`. Each worker loads
the same selected model in a fresh process. The controller restores the
original case order and checks complete coverage.

The five methods, three seeds, training allowance, fresh inputs and final
outcome gates remain those of [step43](../research-step-43/REPORT.md). All
fifteen model choices finish before final scoring starts. Export, retention,
task, BLiMP and story scoring retain their fixed family order. Task and
language cases run in parallel within each family.

## What the records prove

Each worker keeps its command, model and case hashes, output, process status,
wall time, CPU and peak child memory. Its supervisor owns cancellation and
joins every worker. A worker failure cancels its peers and retains partial
records. A deadline also retains every worker receipt.

The parent's process CPU includes the workers it waits for. The study counts
that parent once and keeps worker CPU as a breakdown. A small test uses two
busy children to check this behavior on each platform. In the fixed image,
the parent records 398,531 CPU microseconds and its children record 344,989.
These synthetic values check accounting. The future full comparison will
supply its own measurements. Whole-container peak memory belongs in the
cloud host record.

The checks also cover missing cases, changed worker assignments, invalid CPU
values and expired study deadlines. Eight outcome-rule tests and seven worker
tests pass. The complete native check retains the eighteen altered-record
checks, four training/checkpoint parity checks, historical task parity for
five models, the small CPU-budget case and the invalid native training case.
The latter keeps all five fallback endpoint results with an incomplete status.

The fixed image is bound by digest in [RUNTIME-CHECK.json](RUNTIME-CHECK.json).
It contains GCC 12.2 and Python 3.11.2. Its small check runs with two CPUs,
2 GiB memory, a read-only root and network access disabled. The source kit
repeats the same small study from its extracted files.

what each changed:

- The AWS session expired. Sign-in is pending for the free provider preflight.

  The small fixed-image check therefore runs in CI.
- A Mac path alias made the checker reject an otherwise matching worker
  command. Resolved paths and a full replay after moving the folder now pass.
- Root-owned temporary folders blocked CI artifact upload after the runtime
  checks passed. A scoped permission repair lets the uploader retain them.
- An expired deadline produced a skipped process receipt, while its study row
  was relabelled failed. A controlled reproduction preserves the mismatch.
  The wrapper now keeps the receipt's status, and the regression confirms
  that the expired child stays unstarted.

The earlier scientific failure also repeats. On the tiny synthetic model,
guarded replay accepts all four updates while dialogue endpoint loss rises
about **4.22%** and story bits per byte rise about **17.18%**. Exact task
artifacts remain **0/5**, and the exact parser scores **5/5**. Both guarded
candidates fail the fixed final gate. These opened figures continue to show
why acceptance on the training probe needs a separate retention test.
